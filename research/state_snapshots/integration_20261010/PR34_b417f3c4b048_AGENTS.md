# Research-session entry contract

Before research or implementation work, read `research/RESEARCH_STATE.json`,
`RESEARCH_TRUTH.md`, and the protocol applicable to the proposed change.
The state file indexes the existing history; it does not replace or erase it.

Before finishing, update the canonical state with the actual change, exact
verification, observed failures, unresolved gates, and next action. Preserve
negative and invalid outcomes and the source versions that produced them.
Record a new hypothesis or successor version when scientific behavior changes.

Keep protected evaluation boundaries and existing execution holds explicit.
Engineering tests alone never prove efficacy, complete a scientific checkpoint,
or authorize scientific release. Use a new output identity for any new study.
