# Fabric-Induced Memory — Research Truth

This file defines the claim boundary for the current repository state. It is intentionally conservative: a claim should only move into the supported section when it is backed by reproducible artifacts generated by the checked-in code and configuration.

## Current verdict

**Mechanism-level benefit from the memory/retrieval components is not established by the currently checked-in paper-reference artifacts.**

The repository contains a functioning experimental framework, benchmark code, training/evaluation infrastructure, result-processing utilities, tests, figures, and a paper PDF. Those are useful implementation artifacts, but they are not by themselves evidence that the proposed memory mechanism improves predictive performance.

## Verified repository observations

1. `paper_reference_results.json` records compact values transcribed from `paper/Final FIM.pdf`; it is not labelled as a raw experiment output.
2. The Lorenz ablation values currently recorded there are:
   - full: `1.317169`
   - no_memory: `1.317169`
   - no_retrieval: `1.317169`
   - no_spectral_mixing: `0.869918`
3. On that recorded ablation, the full model, no-memory model, and no-retrieval model are numerically identical, while removing spectral mixing improves the reported score.
4. Therefore the recorded ablation does **not** currently support a claim that memory storage or retrieval is responsible for the reported performance.
5. `scripts/run_ablation.sh` invokes `run_train.py` and passes legacy arguments including `--steps`, `--log_csv`, `--no_memory`, and `--no_retrieval`.
6. The current repository entry point is `main.py`, which delegates to `fim_experiments.main`. The current argument parser does not expose those legacy ablation arguments. The checked-in ablation script therefore requires repair or replacement before it can serve as the reproducible source for the paper ablation.

## Claims that are currently safe

- FIM is an experimental neural sequence-modeling framework with an adaptive memory bank and retrieval path.
- The repository implements benchmarks, training/evaluation code, result processing, and model components for studying the proposed mechanism.
- The repository contains paper-reported reference metrics for several compact benchmarks.
- The current ablation record does not demonstrate a positive contribution from memory or retrieval.

## Claims that are not currently supported

Do not state these as established findings without new reproducible evidence:

- FIM outperforms strong matched baselines because of its memory mechanism.
- Retrieval improves long-horizon forecasting.
- Memory storage improves Lorenz performance.
- FIM is state of the art on any benchmark.
- The current paper-reference metrics have been independently regenerated from the exact checked-in revision.

## Required evidence before strengthening the claim

- Repair the ablation runner so it targets the current training entry point.
- Implement explicit, testable memory-write and retrieval-disable controls in the current model path.
- Run the full, no-memory, no-retrieval, and matched-capacity controls from identical data splits and seeds.
- Use at least three predeclared seeds for each headline comparison.
- Save resolved configuration, commit SHA, environment metadata, per-seed metrics, and raw evaluation outputs.
- Regenerate paper tables and figures directly from those artifacts.
- Explain or resolve the current exact equality between full/no-memory/no-retrieval values.
- Compare against strong non-memory baselines with parameter counts and training budget reported.

## Integrity rule

Negative, null, or contradictory results should be retained. If repaired ablations still show no memory benefit, the paper should frame that outcome directly rather than changing the evaluation until a positive result appears.
