# Research session entry point

Read `research/RESEARCH_STATE.json`, `RESEARCH_TRUTH.md`, and the applicable
protocol before research or implementation work. The root `RESEARCH_STATE.json`
is a navigation pointer to that single canonical index. Read source-specific
predecessor snapshots when relying on their verification or scientific record.

The canonical index preserves history; it does not replace evidence. Earlier
state files and entry rules are retained byte for byte under
`research/state_snapshots/integration_20261010`. Their source-specific assertions,
closed budgets, failures and negative outcomes remain attached to their original
commits. Do not promote inherited test receipts into combined verification.

Before finishing, append actual changes, exact source identities, verification,
observed failures, unresolved gates and the next executable action to the
canonical index. Preserve frozen source identities and all historical outcomes.
Use a new hypothesis/successor version and prospective protocol for scientifically
meaningful changes; never silently reclassify previous evidence.

Engineering tests do not prove efficacy, complete a scientific checkpoint or
authorize scientific release. Protected evaluation and outcome holds remain
explicit. Use a new output identity for a new study; keep each closed session's
budget and artifacts unchanged. No scientific workflow dispatch follows from an
ordinary engineering pull request.
