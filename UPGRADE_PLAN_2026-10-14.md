**FIM and ITFM upgrade plan**

Prepared for Ryan on 14 October 2026. Status: research and implementation proposal. This plan does not change a frozen protocol, reopen a consumed campaign, or claim a new experimental result.

The recommended direction is a separately versioned, observation-safe residual-memory model built around a strong reproduced forecaster. Repair correctness and trainability first; establish that recoverable historical information exists; then add learned addressing, spatial values, selective retention, and calibrated correction only when each improves a controlled comparison. A larger collection of mechanisms is not itself progress.

Perfection is not a feasible acceptance criterion for this task. The current synthetic generator adds independent observation noise with standard deviation 0.03. Even an ideal causal predictor has expected per-coordinate MSE of at least 0.0009. For a fresh distractor with an independent residual of standard deviation 0.75, the lower bound is 0.5634, even if the deterministic mapping is known. These are bounds for unnormalized error on the specified cases, not claims about achieved campaign scores. The proper target is to remove avoidable error, approach the recoverable limit, and demonstrate a useful accuracy–cost advantage on named tasks.

**3. Target model and exact information flow**

The first candidate should be a strong temporal or neural-operator backbone plus an optional residual-memory correction. Keep backbone quality and memory benefit separately measurable. For a forecast made at time t with horizon h:

`base = B(observed history through t, masks, coordinates, known physical parameters, h)`

`query = Q(base state, short causal history, masks, coordinates, h)`

`correction = sum_j weight(query, key_j, age_j, overlap_j) * transport(value_j, geometry_j, h)`

`prediction = base + gate(available reliability features) * correction`

A memory entry contains the episode ID, original forecast ID, input-event time, target-availability and arrival times, horizon, coordinate system, observed residual values, value mask, key-encoder version, backbone version, and normalization version. Retain or hash-reference the original causal source inputs, input masks, saved base forecast, and subsequently observed target entries needed to reconstruct the entry. Include those replay records in storage accounting. At time t, retrieval may use only entries whose observation has actually arrived, from an admitted owner and compatible schema. A target observed at t+h cannot enter the prediction made at t. The prediction used to construct its residual is the saved forecast made before observation; do not recompute it with later information.

For partially observed targets, gather observed indices before subtracting the corresponding saved predictions, then scatter into a sanitized value buffer and retain the mask. Do not use multiplication by zero to hide unavailable NaN/Inf entries. Missing entries are unknown, not measured zeros. With finite sanitized values, coordinatewise aggregation is `sum(weight * valid * value) / sum(weight * valid)`, with an explicit base fallback before division where support is zero. Any learned reconstruction from sparse support is a separately trained component, with imputed values distinguished from observations. Normalization and key construction must also obey visibility restrictions; poisoning tests include finite changes, NaN, and infinity in hidden entries.

Use separate predictor-input and evaluator-truth types. A scorer may know the full target; a query/key/writer may not. This removes the present reliance on every caller remembering to ignore fields in a shared batch object.

Start with the backbone frozen. If backbone weights, latent keys, or residual normalization change, old memory entries become semantically stale. Keep compatible versions immutable, or replay the original causal source inputs and observed targets to rebuild training keys and rebase training residuals under an explicit migration rule. An old residual cannot simply be relabeled as an error of the new backbone. Do not retroactively revise deployed forecasts or use later test information during migration. During representation training, re-encode support observations within bounded episodes so both query and support encoders can learn; do not attach an unbounded autograd graph to persistent deployment memory.

A zero correction gives exact numerical fallback to the base when implemented with an explicit branch. It does not guarantee that a nonzero learned gate is harmless. For residual `r = target - base`, correction c, and scalar g, the change in squared-error risk is:

`R(base + g*c) - R(base) = E[g² ||c||² - 2g <r,c>]`.

The correction helps only if its alignment with the true residual outweighs its added variance. For a fixed scalar and fixed correction, the optimal squared-error scale in [0,1] is `clip(E[<r,c>] / E[||c||²], 0, 1)`, with zero for a zero denominator. Estimate it on a dedicated calibration split. This supplies an interpretable first gate and a clear diagnosis when memory is unhelpful. Finite calibration data and distribution shift prevent a universal no-harm guarantee.

**4. Ordered implementation packages**

All paths below describe proposed work in a new version, for example `successor/itfm_v4/`; that directory is not created by this plan. Port inspected contracts selectively. Keep the predecessor, v2 results, and consumed v3 campaign unchanged.

1. **Observation and event contracts.** Introduce `contracts.py` with separate `PredictorInput`, `ObservedTargetEvent`, and `ScoringTruth`; explicit owner, timestamp, horizon, mask, geometry, and availability semantics. Port only needed pieces from the public `ForecastBatch` contract. Acceptance: future/hidden-target mutation, owner relabeling, batching, and asynchronous-arrival tests all preserve the required invariances. Process by declared arrival order and sequence ID; accept valid late observations for older forecast IDs without revising past predictions. Reject impossible availability, inconsistent duplicates, and malformed events before writing.

2. **A trustworthy reference model.** Implement `models/reference.py` with the frozen base, masked residual storage, deterministic exact retrieval, scalar calibration, and per-row fallback. Use observed values directly before learning compression. Acceptance: saved forecasts independently reconstruct from the event log, masked source values, and recorded weights; a bank miss is exactly the base; kNN comparisons share the same bank and observations.

3. **Trainability and optimization.** Implement `training.py` with declared trainable parameter groups, meaningful gradient probes, delayed reconstruction/retrieval objectives, and staged 1/8/64-trajectory development checks. Use raw checkpoints as the first reference; compare optional EMA using validation, with its decay and update count recorded. Measure the mismatch between in-sample training residuals and out-of-sample residuals; use trajectory-level cross-fitting if that mismatch impairs the adapter, counting the additional fits. If a learned writer remains disconnected, replace it with a deterministic policy rather than calling it learned. Acceptance: solve a deterministic informative training fixture, generalize to fresh noisy episodes within a declared tolerance to the conditional target, and show no hidden-target access. Memorizing fixed noise is not generalization.

4. **Useful addressing.** Add `addressing.py` with a learned query/key metric based on causal state, mask, lead time, and available parameters. Train on training-only support/query episodes with hard negatives that share superficial cues but require different corrections. Hard neighbor selection is not differentiable: top-1 has a constant selected weight and supplies no forecast gradient to the key metric through that route. Use an explicit contrastive/ranking loss with admissible training supervision, or a soft training reader followed by a declared hard reader; measure any training/deployment discrepancy. Compare identity keys, fixed projections, metric learning, and content-plus-age scoring. Keep exact search first. Acceptance: improved retrieval relevance must also reduce held-out forecast error under the same memory budget; better nearest-neighbor labels alone are insufficient.

5. **Spatial values and transport.** Add `values.py` with raw patches as a reference, followed by an optional low-rank or multiscale codec. Retain amplitude and coordinate provenance. Add interpolation or motion/physics-aware transport only for declared transformations. Acceptance: bounded reconstruction loss, correct coordinate transformations, localized responses to local value changes, and improved forecasts over untransported lookup. A powerful transport network must also face a parameter-matched no-memory control.

6. **Selective writing and retention.** Add `retention.py` with per-owner quotas and FIFO, reservoir, diversity/coverage, and utility policies. Learn utility from later observed training outcomes, never from the current evaluation target. Keep irreducible surprise separate from useful novelty: a large residual alone does not make a sample worth retaining. Acceptance: a better accuracy-versus-bank-byte curve, preserved rare-regime recall, and no advantage explained merely by extra stored entries.

7. **Reliability and drift.** Add `calibration.py` with scalar shrinkage first, then a small monotone or local gate using distances, neighbor disagreement, age, observation coverage, and measured correction uncertainty. Base uncertainty alone is inadequate: high base uncertainty may be exactly when memory helps. Add explicit novelty rejection, expiration, and change-point handling as separate hypotheses. Acceptance: lower held-out error, acceptable worst-group harm, and calibrated reliability under fresh keys, missingness, noise, and drift. Return the base when no admissible support exists.

8. **Short and long memory.** After packages 1–7, test a recurrent or state-space short-term state plus a finite episodic bank. Route predictable local dynamics to the backbone and exceptional recurring information to episodic memory. Acceptance: compare against an equally resourced longer-context Transformer/SSM, the episodic-only model, and a wider backbone. Keep the hybrid only if it improves a meaningful accuracy–latency–memory trade-off.

9. **Objective and rollout.** Add `objectives.py` with the deployment-aligned primary loss, explicit query/foreground and background contributions when relevant, and optional multistep, spectral, or conservation terms. Introduce one auxiliary term at a time. Evaluate online observation and open-loop rollout separately. Acceptance: improvement on the frozen primary metric without unacceptable background or long-horizon degradation; physics penalties must correspond to actual boundary conditions and invariants.

10. **Execution that can complete.** Add `runner.py` with a lightweight parent and bounded candidate subprocesses; save candidate checkpoints and release process memory between fits. Use deterministic per-candidate RNG identities. Profile real shapes before setting the prospective time, RAM, output, and compute budgets. Benchmark blockwise exact retrieval and truly windowed attention before approximate indexing: a local attention mask on a full sequence can still construct quadratic work. Retain the existing 512 MiB floor and use additional empirically justified headroom above it. Acceptance: all candidate shapes pass an engineering load probe, and interruption/recovery preserves the exact declared computation.

11. **Independent arithmetic and complete decisions.** Add `verify.py` that reconstructs predictions, permissible reads/writes, metrics, uncertainty, and the complete expected matrix from retained arrays and manifests. Recompute validation predictions and width/temperature/scale selection from raw validation evidence rather than trusting the recorded winner. Bind evaluator and verifier to the same explicit reduction order and macro weighting, while implementing the arithmetic independently. Reject empty output lists, duplicate rows, invalid hashes, missing baselines, nonfinite values, and omitted protocol conditions. Bind protected-evaluation access to actual source/config/data identities, not just strings of the right length. Acceptance: a hostile invalid-artifact test suite fails closed; independently recomputed outputs agree within a tolerance fixed before results are inspected.

12. **Benchmark integration.** Add `backbones/` and `datasets/` only for admitted, version-pinned implementations and data. Reproduce their preprocessing, masks, splits, metrics, checkpoint selection, and validation results before comparing the candidate. Acceptance: upstream reproduction meets a predeclared tolerance, and candidate and comparator see identical information in the comparison track. An interface wrapper or miniature in-house substitute does not count as reproducing the named method.

**5. Broader upgrade candidates and when to use them**

This is a broad research inventory, not a claim to enumerate every possible future invention. The ordered packages above are the initial route; the ideas below are conditional branches, not a combined architecture to build all at once.

| Candidate | Reason to investigate | Principal failure mode and admission test |
|---|---|---|
| Adaptive k or distance cutoff | Fixed top-4 can mix unrelated neighbors | Overfits validation; compare with tuned kNN and fixed-k across unseen key dictionaries. |
| Local linear or ridge residual readout | Similar states may require smoothly transformed corrections | Ill-conditioned fits and extrapolation; use regularization and compare with kernel regression. |
| Learned key whitening or Mahalanobis distance | Raw cue axes may have unequal predictive relevance | Learns spurious mask/domain identity; test mask-only and nuisance permutation controls. |
| Relative spatial coordinates and equivariant features | Recall should follow translations or rotations allowed by the task | Wrong symmetry damages boundary-sensitive physics; test only valid transformations. |
| Multiscale residual patches | Fine detail and global context have different retention costs | Codec erases rare high-frequency events; measure bandwise error and equal-byte recall. |
| Learned latent-value codec | Compresses large fields | Reconstruction loss need not preserve predictive detail; retain raw-value reference. |
| Dual recent and long-term banks | Handles rapid drift and rare recurrence | Duplicate storage or unbalanced quotas; fix total bytes and compare to one bank. |
| Prototype consolidation with uncertainty | Merges repeated observations to reduce noise | Averages distinct regimes; preserve counts, spread, and evidence of multimodality. |
| Age-dependent residual shrinkage | Old residuals become stale under drift | Real recurring regimes can return after long gaps; evaluate recurrence and drift separately. |
| Change-point reset or bank quarantine | Prevents an old regime from dominating | False resets destroy useful memory; report detection delay and false-reset cost. |
| Learned retention utility | Allocates scarce capacity to useful events | Uses future evaluation information or stores unpredictable outliers; train offline and audit timestamps. |
| Coverage-based retention | Avoids duplicate cues occupying the bank | Keeps diverse but irrelevant states; compare utility at equal bytes and retrieval cost. |
| Gated delta-rule fast state | Offers efficient associative updates in a compact recurrent state | Interference and adaptation cost; compare against episodic lookup and official compatible implementations. |
| Local attention plus episodic retrieval | Combines nearby temporal structure and distant recurrence | Gains come from attention alone; require attention-only and wider-backbone controls. |
| Task-conditioned routing among correction experts | Different regimes may need different estimators | Router overfits regime labels; restrict to available features and compare fixed averaging. |
| Masked-observation pretraining | Can learn useful partial-observation representations | Synthetic masks differ from deployment; test unseen mask mechanisms and avoid target leakage. |
| Retrieval curriculum | Easier recall may stabilize representation learning | Curriculum hides hard-case weakness; match total examples and evaluate all difficulty bins. |
| Noise-aware likelihood or ensemble uncertainty | Expresses irreducible uncertainty | Expensive or miscalibrated; score proper likelihood/coverage and count every ensemble member's cost. |
| Physics-aware residual transport | Aligns past corrections with evolving fields | Incorrect PDE assumptions amplify errors; compare against learned/no-transport controls. |
| Conservation or boundary projection | Enforces a known physical constraint | Can conserve the wrong quantity or worsen accuracy; verify the exact invariant and report both effects. |
| Multi-horizon memories | Residual validity can depend on forecast lead time | Cross-horizon contamination; encode horizon and compare separate banks at equal total bytes. |
| Cross-episode retrieval | Could share recurring regimes across trajectories | Changes the information contract and risks split leakage; use a separate training-bank-only track. |
| Online parameter adaptation | Could track changing dynamics beyond simple writes | Test-label tuning and catastrophic forgetting; require a separate protocol with identical adaptation opportunities for baselines. |
| Approximate nearest-neighbor indexing | Reduces large-bank search cost | Changes selected evidence and introduces nondeterminism; require neighbor recall and end-metric equivalence against exact search. |
| Quantization, sparse values, and offloading | Reduces memory footprint | Numeric loss and transfer latency; evaluate error, peak bytes, and tail latency together. |
| Distillation into a compact deployment model | May reduce runtime after a memory teacher succeeds | Distillation loses online adaptability; compare deployment conditions, not only offline imitation. |

Gated delta updates and attention hybrids have primary prior art; their inclusion is an engineering hypothesis rather than a novelty claim. See the [Gated DeltaNet paper](https://arxiv.org/abs/2412.06464) and [official implementation](https://github.com/NVlabs/GatedDeltaNet).

**6. Experiments that distinguish explanations**

Run this ladder on training/development material before any protected comparison:

1. **Information ceiling.** Compare the best feasible current/finite-history predictor with a privileged past-information diagnostic and, where analytically possible, a conditional-mean predictor. For the synthetic generator, distinguish latent anchor access, retained-bank coverage, observation noise, and unobserved drift. The existing most-recent-anchor oracle is not a mathematical lower bound: averaging repeated noisy values can outperform it.

2. **Store and decode.** Give the correct past source index to the readout. If recovery fails, repair value representation, masks, coordinate transport, or optimization before studying retrieval. Keep oracle indices out of ordinary prediction.

3. **Address only.** Hold values fixed and compare raw keys, learned keys, random retrieval, exact lookup, kernel regression, and local linear regression. If learned keys do not improve held-out prediction, retain the simpler representation.

4. **Write and retain only.** Hold the reader and total bytes fixed while varying retention. Measure useful-entry survival and eviction regret using evaluator-only source labels on synthetic tasks. Do not feed those labels into the deployed writer.

5. **Fuse only.** Hold retrieved corrections fixed and compare no correction, scalar shrinkage, channel scaling, and learned gates. Evaluate both helpful and harmful retrieval cases. A gate must outperform an ordinary residual MLP with comparable parameters and information.

6. **Mechanism discrimination.** At fixed weights, delete relevant versus irrelevant entries, mispair keys and values, replace spatial content while preserving scale, and test misses. Report intervention eligibility and coverage. These interventions establish model dependence under controlled perturbations; they do not establish a causal law of the physical system.

7. **Generalization.** Cross noise, recurrence delay, unique keys, bank bytes, distractor rate, drift, observation coverage, horizon, and geometry. Include unseen cue dictionaries and dynamics: v3 currently shares its dictionary/mixing across train/validation/evaluation, so new owners alone do not test that generalization. Separate nonrecurrence and full-observation cases where memory should have little advantage.

8. **Interactions.** Prefer combining changes with individual evidence. Also permit a small prospectively declared factorial experiment for a mechanistically justified complementary pair, such as spatial values × transport, whose individual effects may be weak. Bound that search and its multiplicity in advance. Then remove each component from the final system to determine which contributions survive combination.

Declare the development search budget and promotion rule in advance. Use separate training, architecture-selection, and gate-calibration partitions where data permits; all partitions remain separate from the final test. Count failed fits and all tuning trials. Do not transfer validation winner status into a claim that every comparator was beaten on test.

**7. What a defensible SOTA comparison requires**

Use two named scientific tracks already contemplated by the repository: partial-observation operator learning, and non-Markovian/delay-PDE forecasting. Synthetic recall remains a mechanism track. It cannot substitute for either scientific benchmark.

The primary sources checked for this plan identify relevant comparators, not a complete October 2026 leaderboard:

- [LANO and POBench-PDE](https://arxiv.org/abs/2601.15547v2) address partial-observation operator learning. Reproduce the exact admitted protocol before testing a memory adapter. If the official task does not expose past observations with the required timing, create a separately named online extension and give every baseline that information; do not call the changed task an official leaderboard result.
- [HS-FNO](https://arxiv.org/abs/2605.09523v2) uses an exact shift-append history update for non-Markovian PDE forecasting. Its history-aware baseline is essential; a current-state FNO alone does not isolate memory value.
- [MemNO](https://arxiv.org/abs/2409.02313v2) is directly relevant to coarse/noisy observations and temporal memory. It establishes that the general problem is occupied prior art.
- [SS-NO](https://arxiv.org/abs/2507.23428v5) is the revised March 2026 version of the paper called ST-SSM in older local audits. Refresh the baseline registry to a pinned version and actual implementation rather than inheriting the old title or algorithm description.
- [The Well](https://github.com/PolymathicAI/the_well) is a candidate later source of broader physics tests, after bounded development and admission. Select a declared manageable subset; downloading a large collection is not an experiment.

For each track, require the official or paper-faithful frontier model, an equally tuned longer-context temporal model, a parameter-matched residual predictor, persistence/appropriate simple physical controls, and simple residual retrieval on the identical bank. Architecture labels in the historical mini-suite do not certify current official implementations.

Report two complementary comparisons: a controlled shared-backbone experiment to isolate memory, and each strong method's best admitted recipe under a common resource envelope. Equal update counts do not equal compute fairness. Record training examples, optimization steps, tuning trials, total accelerator/CPU time, inference throughput, p50/p95 latency, peak memory, persistent state bytes, and parameters. Measure FLOPs where a trustworthy implementation exists; otherwise report them as unavailable. Count pretraining, bank construction, retrieval, rebuilding, and adaptation costs separately.

Keep the existing frozen public protocol intact. It already proposes substantial hurdles: at least 10% macro improvement and 30/36 wins on its primary track, no cell worse by more than 2%, and a secondary 15% gain with four of five family wins and no family worse by more than 2%. Its secondary absolute target of 0.0799 derives from a reported 0.094 reference and is meaningful only if preprocessing, aggregation, and reproduction match. A new successor protocol must explicitly retain or prospectively justify changes to these targets; do not silently soften them after outcomes. Passing them would support claims about the tested suites and settings, not universal dominance.

The final statistical plan must define the estimand, aggregation, missing/failed-cell treatment, and multiplicity family before test access. Macro-average declared cells rather than accidentally weighting datasets by trajectory count. Separate data-generation, split/mask, and optimization RNG axes: v3 currently changes both the generated task and the fit when its seed changes. Treat independent trajectories or subjects as data units and optimization seeds as algorithmic variability; preserve the actual crossed or nested dependence in resampling. Three or five PDE families cannot establish broad population generalization. Use development-only power analysis to choose replication counts and a practical effect threshold. Five pairs cannot attain a two-sided exact sign-flip p-value below 0.0625. Additional seeds must follow a prospective sample-size or sequential design, not a search for significance.

Report paired effects and uncertainty against all required competitors, with the planned correction for multiple comparisons. A validation-selected baseline may be the declared primary comparator, but report every other test comparison too. Near-zero baseline errors require a prospectively defined absolute-scale safeguard for relative gains. Independent reproduction requires a fresh operator and environment using the frozen package; another run by the same operator is useful reproducibility evidence with a narrower meaning.

**8. Execution sequence and stopping rules**

| Stage | Deliverable | Advance only if | If it fails |
|---|---|---|---|
| A: source and evidence boundary | New version identity, preserved predecessor hashes, explicit known defects and proposed protocol changes | Existing evidence remains intact and the source of each result is identified | Resolve provenance without rewriting historical outputs. |
| B: correctness and visibility | Packages 1, 2, 3, and 11 with numerical gradient and noninterference tests | No future/hidden-target access, batch coupling, disconnected declared learned head, or false-pass decision remains in the tested contracts | Repair the defect; do not spend a scientific campaign. |
| C: execution feasibility | Full-shape profile, measured RAM/time/output estimates, recovery equivalence, bounded budget | Every candidate fits admitted resources with a declared safety margin | Reduce engineering overhead or use an admitted adequate host; preserve the floor and failed receipts. |
| D: recoverable memory value | Past-information diagnostic and matched simple-control development study | There is evidence of a useful recoverable gap under the admitted information/capacity contract | A failed proxy oracle stops or redesigns that residual-store route; it does not prove all history uninformative. A stronger impossibility claim needs a proven information ceiling. |
| E: minimal reference | Frozen-base masked spatial residual memory plus scalar gate | Independent implementations agree; costs, harm, and the remaining recoverable gap are measured | Repair incorrect reference behavior. If a correct reference loses but the diagnostic gap remains, use the localized failure to select a bounded upgrade. |
| F: justified upgrades | Individually tested improvements and limited interaction study | A genuinely different candidate improves over the strongest simple retrieval and history controls at the declared budget, with acceptable harm and informative removal ablations | Keep the simpler winner or close the bounded search without a memory-advantage claim. |
| G: public reproduction and freeze | Admitted data/source, reproduced comparators, exact final protocol and locked test access | Upstream reproduction, oracle triage, and resource/budget requirements pass | Record blocked or failed reproduction; no SOTA interpretation. |
| H: final evaluation | Complete frozen matrix, raw arrays, costs, independent arithmetic | All required cells and all decision gates are evaluable and satisfied | Report mixed, negative, invalid, or incomplete results exactly; retain every failure. |
| I: independent reproduction | Fresh-operator replication and scope-limited claim | Frozen results and decision reproduce within the declared standard | Resolve discrepancies and preserve both results. |

The observed v3 interruption does not establish a memory leak: its guard measures global available memory. Retaining several trained candidates in one process is a plausible source of avoidable pressure, but host activity and allocator behavior must be measured. Process isolation and checkpoint streaming address this hypothesis without assuming it is the only cause.

For a new protocol, define an interruption policy before outcome access. A permitted continuation must restore model, optimizer, scheduler, mixed-precision scaler, RNG, sampler position, memory contents, normalization, and consumed budgets; prove its equivalence to an uninterrupted reference where required. It must not silently add optimization or selection opportunities. The existing consumed v3 version has no such reopened allowance and remains untouched.

No honest GPU-hour estimate follows from the present evidence. Profile each family on development material, estimate training plus tuning plus inference plus verification, then select and authorize a bounded execution budget. Passing the 512 MiB minimum is necessary admission in the existing workflow, not evidence that a full-size training job fits.

**9. Conditions that would reject the proposed direction**

Reject a claim of extra memory information if a valid information analysis establishes that the admitted history provides none beyond the strong base. Reject the case for a more complex memory architecture if simple kNN matches it at lower cost; that result can still support ordinary retrieval. Close the bounded memory-advantage search if a longer-context model matches or beats its candidates within the budget, if gains disappear after fixing visibility or capacity imbalance, if corrections systematically harm new regimes, or if public-data effects fail the predefined criteria. A failed approximate oracle alone does not establish that history is useless. A useful backbone upgrade can survive a rejected memory claim, but it is a different contribution.

Remaining research uncertainties are explicit: future residual predictability, representation transfer, useful retention under finite bytes, reliable gating under shift, adequate baseline convergence, and generalization beyond tested dynamics. Each has an experiment and a stopping rule above. A successful plan makes these uncertainties answerable and failures visible; it cannot truthfully promise that all future tests will pass.

The first implementation milestone is therefore the observation-safe reference, gradient audit, batch/owner invariance, and complete decision verifier. The first scientific milestone is to localize a recoverable gap and determine how much the simple reference captures. A proposed architectural improvement must then beat that reference and strong history controls under the same information and resource contract. Larger architectures require a specific measured bottleneck or a bounded, prospectively justified interaction experiment.
